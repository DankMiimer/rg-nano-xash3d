# Improvement roadmap

1. **Observe and recover (implemented):** bounded crash/output logs, RAM/swap/CPU samples, owned-process shutdown and automatic clock/key restoration. Verify normal exit, crashes and manual recovery before investigating death freezes further.
2. **Remove the unknown binary dependency (built and running separately):** build FWGS engine, filesystem, renderer, menu and HLSDK libraries with the FunKey SDK; test a separate framebuffer/evdev/ALSA installation. Preserve the working SDL ports until display, navigation, shooting and sound pass on real hardware.
3. **Measure memory and stalls (bounded longer runs completed):** [PERFORMANCE.md](PERFORMANCE.md) records frame-scheduling comparisons; [STABILITY.md](STABILITY.md) records over 24 minutes of combined CS/HL process continuity, death/spectator periods, saves/loads and level changes at 1200 MHz. Paging and loading stalls remain. Next attribute texture/model/sound memory and measure representative later campaign scenes before changing cache budgets.
4. **Repair HUD rendering (spectator geometry corrected; independent HUD profile implemented):** check sprite clipping, transparency and software-renderer scaling with representative HL and CS scenes. Preserve original sprites, colors and corner placement; validate independent element scales, whole-block edge placement, symmetric crosshair and separate menu libraries. Distinguish corrupt rendering from layout or font size. See [HUD-CONTROLLER-RESEARCH.md](HUD-CONTROLLER-RESEARCH.md) for candidates and the implementation sequence.
5. **Tune control ergonomics:** use X fire/Y reload, R + D-pad vertical look/strafing, slow default aim with L fast look, working number menus and system shortcuts. Horizontal hold acceleration is implemented and user-confirmed; pitch and movement do not ramp. Add alternate profiles only after physical-device feedback.
6. **Optimize demonstrated bottlenecks (two allocation reductions implemented):** [MEMORY.md](MEMORY.md) records the counter-only `nano_mem`/`nano_tex` commands, approximately 10 MiB saved by removing unused menu/sprite/studio mips and a further 17 MiB from sharing identical converted texture buffers in CS. Texture reuploads replace their references safely. Low-memory model source truncation already exists upstream. Limited available RAM and paging remain. [LOADING-AUDIO.md](LOADING-AUDIO.md) records opt-in peak intervals, roughly 3.6–3.9 MiB temporary overhead during HL transitions/CS loads, and tested targeted speaker-volume restoration that avoids the broad mixer startup scan. [DEMAND-ZERO.md](DEMAND-ZERO.md) records the implemented large-cleared-buffer path, its approximately 4 MiB fresh-buffer RSS reduction in an actual pool-code probe, and bounded saves/transitions/reload checks. Save capacity and custom-swap pairing are preserved. Next use repeated baseline/candidate transition measurements with a controlled cache policy, then measure animation/header storage and representative later scenes before changing quality or cache budgets. The underlying firmware driver lock remains unresolved. Specialized dialogs/editors still need layout work. Framebuffer double buffering and newer engine revisions remain separate experiments; check renderer interfaces when changing the engine pin.
7. **Reproducible releases:** publish source and recipes with pinned dependencies and notices. Distribute no Valve data, extracted icons, unlicensed fonts/NAV or unknown base-port binaries. Only consider source-built binary releases after dependency-license and hardware parity checks.

Relevant upstream references: [FWGS engine](https://github.com/FWGS/xash3d-fwgs), [portable HLSDK](https://github.com/FWGS/hlsdk-portable), [CS16Client](https://github.com/Velaron/cs16-client), and [FunKey OS/SDK](https://github.com/FunKey-Project/FunKey-OS). See [VALIDATION.md](VALIDATION.md) for completed checks and limits.
